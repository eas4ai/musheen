# Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce a runnable, read-only Musheen shell that lists local folders through a lossless, paged store abstraction and follows the native Linux theme.

**Architecture:** Establish the workspace boundaries in the plan index. `musheen-core` owns portable contracts, `musheen-local` is the only local filesystem implementation, and `musheen-ui` consumes models and commands without filesystem access.

**Tech Stack:** Rust 2024, GPUI Kit 0.6.2, native-theme 0.5, freedesktop crates, nix, rustix, walkdir, notify, camino for UTF-8 configuration only, and the GPUI Kit Lucide assets.

`rust-toolchain.toml`, `deny.toml`, `ci/linux-build.Dockerfile`,
`scripts/check-linux-build.sh`, and each crate's `Cargo.toml` and `src/lib.rs`
under `crates/`.

- [ ] Add a failing workspace test in `tests/workspace_boundaries.rs` that
  asserts all six crates exist and that only `musheen-local` contains local
  filesystem calls.
- [ ] Run `cargo test --test workspace_boundaries`; expect failure because the
  workspace has not been created.
- [ ] Add workspace members `musheen-core`, `musheen-local`, `musheen-ops`,
  `musheen-desktop`, `musheen-ui`, and `musheen-test-support`; keep the root
  binary as the composition root and set `rust-version = "1.95"`.
- [ ] Add workspace lint policy (`unsafe_code = "forbid"`, Clippy warnings as
  errors in local verification) and GPL-3.0-or-later package metadata.
- [ ] Make the Linux build script archive the exact commit and run one Docker
  container at a time; do not add a GitHub Actions development workflow.
- [ ] Run `cargo fmt --check`, `cargo clippy --workspace --all-targets --all-features -- -D warnings`,
  `cargo test --workspace`, and `cargo build --locked`.
- [ ] Commit with `build: establish musheen workspace boundaries`.

### Task 2: Implement lossless core identities and capabilities

**Files:** Create `crates/musheen-core/src/{path,item,capability,limits,error}.rs`;
create `crates/musheen-core/tests/{path_roundtrip,capabilities,limits}.rs`.

- [ ] Write tests constructing a Unix path from `b"bad-\xff-name"`, proving
  display text cannot become an operation path implicitly, and requiring every
  `CapabilityKind` to resolve to `Supported`, `Unsupported(reason)`, or
  `Unknown(reason)`.
- [ ] Run `cargo test -p musheen-core --test path_roundtrip --test capabilities`;
  expect unresolved-type failures.
- [ ] Implement `ProviderId`, opaque `ItemId`, `StorePath` with Unix-byte and
  provider-key variants, separate `DisplayPath`, the complete capability enum,
  and immutable `ResourceLimits` snapshots.
- [ ] Add compile-fail coverage with `trybuild` showing that `DisplayPath`
  cannot be passed where `StorePath` is required.
- [ ] Run `cargo test -p musheen-core`; expect all core tests to pass.
- [ ] Commit with `feat(core): add lossless paths and capability matrix`.

### Task 3: Define the paged store contract

**Files:** Create `crates/musheen-core/src/{store,page,cancel,watch}.rs` and
`crates/musheen-test-support/src/{recording_store,fixtures}.rs`; create
`crates/musheen-core/tests/store_contract.rs`.

- [ ] Write contract tests for 512-item pages, two-page prefetch, stable IDs,
  cancellation between pages, explicit unsupported operations, watch overflow,
  and reconciliation without duplicate items.
- [ ] Run `cargo test -p musheen-core --test store_contract`; expect failure.
- [ ] Define object-safe `Store` and `DirectoryWatch` traits returning boxed
  futures, plus `PageRequest`, `Page<T>`, `Continuation`, `CancellationToken`,
  and typed `StoreError`. Mutation methods must reject by capability before
  producing work.
- [ ] Implement a recording provider and delayed million-item fixture without
  allocating one million item models at once.
- [ ] Run the contract test under `timeout 60s`; verify cancellation and model
  counters remain bounded.
- [ ] Commit with `feat(core): define paged store provider contract`.

### Task 4: Build the read-only local provider

**Files:** Create `crates/musheen-local/src/{lib,enumerate,traverse,watch,probe,metadata}.rs`;
create `crates/musheen-local/tests/{contract,hostile_paths,watch_recovery}.rs`.

- [ ] Add fixtures for non-UTF-8 names, permission denial, symlink loops,
  external rename, watch overflow, sparse files, and case-sensitive names.
- [ ] Run `cargo test -p musheen-local`; expect missing-provider failures.
- [ ] Implement paged `read_dir`, bounded `walkdir` traversal, notify watches,
  mount/filesystem probing through nix and proc-mounts, and stable local IDs
  derived from device and inode with a documented replacement fallback.
- [ ] Ensure traversal never follows symlinks by default and no UI/ops crate
  imports `std::fs`.
- [ ] Run `cargo test -p musheen-local` and the shared provider contract suite.
- [ ] Commit with `feat(local): add lossless read-only filesystem provider`.

### Task 5: Add the command registry and durable settings schema

**Files:** Create `crates/musheen-core/src/command.rs` and
`crates/musheen-desktop/src/settings.rs`; create tests in both modules.

- [ ] Test that a command has one stable ID, label key, icon key, shortcuts,
  capability predicate, and handler regardless of toolbar, menu, or palette
  presentation. Test atomic settings writes and recovery from a corrupt file.
- [ ] Run the two targeted test modules; expect failure.
- [ ] Implement the registry and a versioned settings document under the XDG

- [ ] Register navigation, view, refresh, selection, and settings commands;
  mutation commands remain absent, not enabled placeholders.
- [ ] Run `cargo test -p musheen-core command` and
  `cargo test -p musheen-desktop settings`; expect both targeted suites to pass.
- [ ] Commit with `feat: add command registry and settings persistence`.
